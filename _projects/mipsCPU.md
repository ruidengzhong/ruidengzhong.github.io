## Project Overview
I designed and implemented a complete 16-bit MIPS-style processor at the gate level using Logisim. The project involved building the processor’s datapath and control logic from fundamental digital components rather than relying on prebuilt CPU modules.

The processor supports arithmetic, logical, memory-access, and control-flow instructions. It includes separate instruction and data memory blocks, a custom arithmetic logic unit, a register file, a control unit, a program counter, shifters, counters, and a 16-bit ripple-carry adder/subtractor.

This project provided hands-on experience with computer architecture, digital logic design, instruction execution, datapath organization, and control-signal generation.

## Processor Architecture
The CPU follows a MIPS-inspired architecture in which instructions are fetched from instruction memory, decoded by the control unit, executed by the datapath, and used to update the processor state.

The primary execution stages are:

1. Instruction fetch
- The program counter addresses instruction memory and retrieves the next 16-bit instruction.
2. Instruction decode
- The control unit interprets the opcode and instruction fields, identifying the required operation and generating the corresponding control signals.
3. Register read
- Source operands are selected from the register file and routed to the appropriate datapath components.
4. Execution
- Arithmetic, logical, comparison, or shift operations are performed by the ALU and associated logic.
5. Memory access
- Load and store instructions interact with the data memory block using an address generated by the datapath.
6. Write-back and state update
- Results are written back to the selected register when required, and the program counter is updated for sequential execution or control-flow instructions.

## Custom Arithmetic Logic Unit
I designed a custom ALU to perform the processor’s arithmetic and logical operations. The ALU was constructed from gate-level combinational logic and multiplexers that select the required operation based on control signals from the control unit.

The ALU supports operations such as:

- Addition
- Subtraction
- Bitwise AND
- Bitwise OR
- Bitwise XOR
- Comparisons
- Shift-related operations
- Status or condition outputs used by control-flow instructions

The ALU also generates relevant result information, such as whether the output is zero. This signal can be used to evaluate conditional branch instructions.

## 16-Bit Ripple-Carry Adder/Subtractor
The arithmetic datapath includes a custom 16-bit ripple-carry adder/subtractor. The circuit is constructed from cascaded full-adder stages, with the carry output of each bit connected to the carry input of the next bit.

Subtraction is implemented using two’s-complement arithmetic. One operand is conditionally inverted, and the initial carry input is modified to add one. This design allowed the same hardware to perform both addition and subtraction while demonstrating how arithmetic operations can be implemented from basic gates.

## Register File and Gate-Level Registers
I designed the processor’s registers at the gate level. Each register stores a 16-bit value and uses clocked control signals to determine when new data is written.

The register system includes:

- Multiple 16-bit general-purpose registers
- Register selection logic
- Read-path multiplexers
- Write-decoding logic
- Clock and write-enable control
- Reset behavior where required

The register file allows instructions to read source operands and write execution results. Multiplexers select the appropriate register outputs, while the control unit determines which register receives new data during the write-back stage.

## Program Counter and Control-Flow Hardware
The processor uses a program counter to track the address of the current instruction. I designed the supporting counter and selection logic to allow the processor to either continue sequentially or redirect execution.

The next program-counter value can be selected from several sources, including:

- The incremented program counter
- A branch target address
- A jump target address
- Other control-flow destinations defined by the instruction set

This required integrating adders, sign-extension or immediate-processing logic, shift operations, and multiplexers. Conditional branches use control signals and ALU-generated comparison results to determine whether the program counter should change.

## Shifters and Immediate Processing
The processor includes custom shifter circuits for instructions that require bit movement. The shifters support operations such as:

- Logical left shifts
- Logical right shifts
- Other shift modes defined by the instruction format

Immediate values from instructions are routed through the appropriate extension and alignment logic before being used by the ALU, memory address calculation, or branch-target calculation.

These circuits were implemented using combinations of wiring, multiplexers, and gate-level logic.

## Custom Control Unit
I designed a custom control unit to decode instructions and generate the datapath control signals required for each instruction type.

The control unit determines:

- Which ALU operation is selected
- Which registers are read
- Which register receives a result
- Whether the ALU uses a register or immediate operand
- Whether data memory is read or written
- Whether the write-back value comes from the ALU or memory
- Whether the program counter follows the sequential or control-flow path
- Whether a branch condition is satisfied

The control logic was implemented using opcode-decoding logic and combinational control-signal generation. Designing the control unit required mapping each instruction to the correct sequence of datapath operations and ensuring that unused control signals did not interfere with execution.

## Instruction and Data Memory
The processor uses separate memory blocks for instructions and data.

#### Instruction Memory
Instruction memory stores the program executed by the CPU. The program counter provides the address, and the selected 16-bit instruction is routed to the decoder and datapath.

#### Data Memory
Data memory supports load and store instructions. The ALU calculates the effective memory address, and control signals determine whether the processor reads from or writes to that location.

Using separate instruction and data memory blocks simplifies the datapath and allows instruction fetching and data access to be treated as independent operations.

## Supported Instruction Categories
The processor supports multiple instruction classes, including:

#### Arithmetic Instructions
Arithmetic operations use register or immediate operands and write the result back to the register file.

Examples include:

- Addition
- Subtraction
- Immediate arithmetic operations

#### Logical Instructions
Logical operations perform bitwise manipulation on register values.

Examples include:

- AND
- OR
- XOR
- Logical comparisons

#### Memory Instructions
Memory instructions calculate an address using the ALU and access the data memory block.

Supported operations include:

- Load data from memory into a register
- Store register data into memory

#### Shift Instructions
Shift instructions use the custom shifter hardware to move bits within a 16-bit operand.

#### Control-Flow Instructions
Control-flow instructions modify normal sequential execution by changing the program counter.

These include:

- Conditional branches
- Unconditional jumps
- Branches based on ALU comparison or zero-detection results

## Datapath Integration
The processor’s datapath is connected using buses and multiplexers that route values between the register file, ALU, memory, shifters, and program-counter logic.

Important datapath decisions include:

- Selecting register or immediate operands for the ALU
- Selecting an ALU result or memory output for register write-back
- Selecting the appropriate destination register
- Choosing the next program-counter source
- Routing memory addresses and write data
- Connecting branch and comparison results to the control-flow logic

The final processor integrates these blocks into a complete instruction-execution system.

## Verification and Debugging
Because the processor was built at the gate level, debugging required checking both individual components and their interactions. Testing included:

- Verifying individual gates and combinational circuits
- Testing the 16-bit adder and subtractor
- Confirming register read and write behavior
- Testing ALU operation selection
- Checking shifter outputs
- Verifying instruction decoding
- Testing load and store operations
- Confirming program-counter updates
- Running short instruction sequences
- Tracing control signals through the complete datapath

Logisim’s visual simulation environment made it possible to observe internal buses, registers, control signals, memory addresses, and intermediate ALU results during execution.

## Project Outcome
The completed Logisim design functions as a programmable 16-bit MIPS-style CPU built from custom gate-level components. It can fetch and decode instructions, execute arithmetic and logical operations, access separate instruction and data memories, update registers, perform shifts, and change program flow through branches and jumps.

The project required integrating many independent digital subsystems into a reliable processor datapath and control architecture. It provided practical experience translating an instruction set into hardware and understanding how modern processors execute programs at the level of gates, registers, buses, and control signals.
